# PS-2026-076 — Alpha 1 false-positive prior-station lineage detection

## Finding

The recovery gate correctly protected ambiguous data, but its current-workspace evidence classifier treated Pine Star's own pre-onboarding loop and Night Shift safety state as proof of a prior station. The live Alpha report's only current-workspace evidence was `loops.halt.json`, `nightshift.state.json`, and their normal resilient `.bak` copies. Night Shift had used zero beats and had never fired; recovery found no station save or candidate.

The files are legitimate before onboarding because the global E-STOP durably stamps the loop and Night Shift halt stores independently of whether a loop, beat, or station save exists. The common resilient writer creates the corresponding `.bak` snapshots on later writes. Filename presence alone therefore could not distinguish safety scaffolding from user station state.

## Change

- Exclude only the exact `loops.halt.json[.bak]` envelope `{ halted: boolean }`.
- Exclude only exact version-1 `nightshift.state.json[.bak]` envelopes whose `beatsUsedToday` and `lastBeatAt` are both zero and whose remaining fields are valid non-negative integers.
- Treat malformed, extended, or activity-bearing versions of those files as evidence.
- Continue treating saves (including corrupt/unreadable generations), station identity/configuration, durable work/history, migration and recovery evidence, and unknown workspace files as prior-state evidence.
- Keep lineage inspection read-only. No control file is deleted, moved, rewritten, recovered, or cleared.

This is meaning-based and independent of `recoverableCount`; a corrupt real save still blocks with zero recoverable candidates. The E-STOP and Night Shift persistence/load paths are unchanged.
