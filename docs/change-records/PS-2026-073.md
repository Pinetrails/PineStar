# PS-2026-073 — Auditor deterministic-fact boundary

## Authorization and decision

Commander accepted the PS-2026-072 `retain_champion_no_candidate` result. The current champion `operations-auditor.ollama-llama3.2-3b.v1` remains active without any claim that its measured quality is adequate. The challenger remains inactive, no configuration candidate is created, and the closed experiment is not rerun or altered.

Commander established the architectural rule that deterministic mechanical checks are authoritative for facts that can be computed exactly. Auditor models may interpret verified findings, explain significance, prioritize anomalies, summarize evidence, state uncertainty, and recommend bounded follow-up. They may not override JSON validity, record counts, schema/state invariants, exact reference integrity, roster/configuration joins, or other directly computable facts.

## Smallest dependency-ready implementation

The existing `objectiveStore.createAudit` path remains the single Auditor workflow. Before creating model work, it now calls the PS-2026-071/072 `auditor-json-audit-v2` verifier against the settled target record. The resulting immutable-shaped bundle is persisted inside `auditRequest.verifiedFacts` with:

- deterministic authority and verifier-contract identity;
- target identity and settled status;
- exact completion-evidence references;
- JSON validity, record count, issue count, and exact issue markers;
- bounded source/provenance references.

The normal Auditor directive includes this verified block and explicitly prohibits recalculation, contradiction, replacement, or override. Model work is limited to `modelInterpretation`, `uncertainty`, and `recommendedFollowUp`.

Audit descriptions have a dedicated bounded 10,000-character ceiling so the complete verified block and bounded evidence survive construction; other objective descriptions retain their existing 2,000-character limit. Optional caller text is treated only as model scope and cannot replace the hybrid directive.

`composeReport` creates `pine-star.hybrid-auditor-report.v1` with four visibly separate fields: `verifiedFact`, `modelInterpretation`, `uncertainty`, and `recommendedFollowUp`. It copies verified facts only from the durable audit request and rejects any additional model field, including a model-authored `verifiedFact`. This establishes a safe dependency boundary for normal runtime/report integration without adding a parallel audit store, model runner, route, provider, or configuration.

## Alpha 1 direction

Pine Star is ready to begin Alpha 1 hands-on testing of this local/internal Auditor boundary. Hands-on testing should confirm that real audit objectives show deterministic facts as authoritative and model interpretation as advisory, including useful uncertainty and follow-up. This is not release readiness, publication authority, or evidence that the retained 3B champion is an adequate fact verifier.
