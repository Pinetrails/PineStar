# PS-2026-015 — Recurring Objective Scheduler Bridge

**Date:** 2026-08-27  
**Status:** Complete

## Intent

Make Pine Star objectives safely recurring by adapting the mature StarNet scheduler rather than creating another scheduler, timer, execution engine, halt system, or recovery store.

## Implementation

- Added a bounded recurring-definition contract with stable schedule ID, owning system role, recurrence/timezone, enabled state, and an objective template containing title, description, capabilities, tier ceiling, priority, and protected-action status.
- Definitions are existing cron jobs in protected `cron.jobs.json`. Pine Star provenance lives in bounded `meta.pineStarRecurring`; delivery is local, unattended grants are empty, and line execution is disabled.
- Creation uses the existing schedule parser, mint path, durable cron lock/write, and next-fire calculation. Same ID and signature is idempotent; conflicting reuse is rejected.
- Enabling requires one active capable system role and exactly one roster identity explicitly bound through `systemRoleIds`. Disabled definitions may be prepared without a binding but cannot execute.
- Added one optional cron-driver callback. A Pine Star-tagged fire delegates to objective occurrence creation, admission, activation, and settlement and skips cron's direct `runOnce`. Ordinary cron jobs stay on the unchanged path.
- Occurrence keys bind schedule and scheduled fire. Exact retries return the same record; a shifted retry also reuses unresolved work for that schedule. Once the prior occurrence is completed, failed, or cancelled, a later genuine recurrence may create a new record.
- Protected occurrences remain `approval_required`. Safe occurrences route to the declared specialist, admit through the existing runtime-role binding, activate through shared `runOnce`, and settle through the objective lifecycle.
- Cron's advance-before-run, locks, global armed state, durable halt, leases, E-stop abort, cancellation, failure counters/auto-pause, restart recovery, and finalization remain authoritative. Objective cancellation receives the cron abort signal.
- Added authenticated create/list and enable/disable APIs backed by cron records. Inspection exposes next/last run, last outcome/error, retry and consecutive-failure counts, disabled reason, and scheduler state.
- Added the `open-source-scout` recurring workflow, which forces the Scout role/capabilities/economy tier and reuses the existing no-install directive and structured Scout report marker.

## Safety

- Spending authority remains `$0`; no unattended grant is added.
- No automatic approval, publishing, messaging, installation, downloaded-code execution, credential expansion, account/subscription action, or E-stop bypass was introduced.
- Provider/model readiness and permissions remain in objective admission/activation. Protected recurring work never executes without the existing legitimate approval state.
- No migration, external action, or push occurred.
