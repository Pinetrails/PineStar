# PS-2026-075 — Alpha 1 dev-origin CORS parity

## Finding

PS-074 repaired missing desktop API authentication. The resulting authenticated request exposed a second dev-only transport issue: the Tauri dev WebView origin was `http://127.0.0.1:1430` while sidecar CORS only recognized the packaged Tauri origin.

The Tauri configuration uses `frontendDist` without an external `devUrl`; `tauri dev` therefore owns and serves the development WebView on its fixed CLI loopback origin. The sidecar correctly rejected that origin because it differed from both its own dynamic port and the packaged Tauri origins.

## Change

- Added the single exact development origin `http://127.0.0.1:1430` to the pure origin decision, conditional on an explicit development allowance.
- The Rust desktop host supplies `STARNET_TAURI_DEV=1` (and the legacy alias) only in a `debug_assertions` build.
- The sidecar activates the allowance only when both `STARNET_DESKTOP_SHELL` and the debug marker are true.
- Packaged origins remain in the existing fixed allowlist. Release desktop builds do not emit the debug marker, so the development origin remains forbidden there.

No wildcard, arbitrary-port match, general Origin reflection, CSP change, public API route, or authentication exemption was added. Protected routes still require the per-launch `X-StarNet-Token`; Host validation and query-token exceptions are unchanged.
