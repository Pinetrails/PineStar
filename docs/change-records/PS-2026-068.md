# PS-2026-068 — Local Ollama operational envelope

## Decision

Pine Star local Ollama uses a 240,000 ms first-response/header deadline and zero pre-header retries. This is a bounded operational ceiling, not a guarantee that every installed model completes. Failure to return headers within the ceiling is a truthful timeout and valid configuration-performance evidence.

Representative accepted validation measured `llama3.2:3b` at 1.020s (~4k warm), 78.003s (~7k warm), and 226.144s (~9k cold/nonresident). `llama3.1:latest` measured 34.366s (~4k warm), 172.695s (~7k warm), and no headers before the 240.047s diagnostic ceiling (~9k cold/nonresident). A separate cancellation probe aborted in 107ms after a scheduled 100ms cancellation. Every probe was local, single-attempt, deterministic, no-fallback, non-evidence, and `$0` external cost.

## Implementation and boundaries

- The Ollama registry profile owns `connectTimeoutMs: 240000` and `preHeaderRetries: 0`.
- The provider factory passes these fields only for the exact `ollama` profile. A positive explicit shorter connect deadline is allowed; requests above 240,000 ms are clamped and retry requests are clamped to zero.
- External/custom OpenAI-compatible providers receive no new setting and retain the shared default: 30,000 ms per connect attempt and two pre-header retries (three attempts total).
- The 300,000 ms resettable stream-idle watchdog is unchanged. Connect guards still disarm at headers.
- Cancellation remains distinct from timeout and returns promptly without retry. Existing E-stop, fallback/model substitution, cost, audit/provenance, and production-configuration boundaries are unchanged.
- Worst-case Ollama pre-header failure envelope is one attempt at 240,000 ms, with no retry backoff. Scheduler/host overhead may add negligible wall-clock settlement time.
