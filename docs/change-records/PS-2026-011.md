# PS-2026-011 — Safe Objective Activation

**Date:** 2026-08-27
**Status:** Complete
**Type:** Phase 4 objective execution lifecycle
**Git commit:** The commit containing this record

## Purpose

Activate an admitted Pine Star objective through StarNet's existing execution authority while preserving identity, consent, cancellation, E-stop, audit, billing, failure, and settlement behavior.

## Implementation

- Added an activation contract that accepts only a non-protected `admitted` objective and revalidates its stable role and live roster binding.
- Reused the admission-minted run ID and synchronously registered one controller in `runs`/`runsMeta` before persisting `in_progress`.
- Calls `runOnce` with the bound roster identity, `surface:'autonomous'`, no interactive consent/login/summon channel, no owner trust, no new path grants, and no unattended tool grants.
- Existing runtime provider/model resolution, concurrency, billing, permissions, journals, transcripts, run history, cancellation, and E-stop remain authoritative.
- Added authenticated `POST /api/objectives/activate` and `POST /api/objectives/cancel`.
- Settles only real `done` as completed; abort/halt/cancel becomes cancelled; refusal, non-done, or thrown execution becomes failed.
- Stores bounded run/artifact evidence, reason, result summary, timestamps, and lifecycle audit without copying raw transcripts.
- Duplicate live activation is rejected. An orphaned `in_progress` record after restart is durably failed as interrupted and never silently executed twice.
- Extended the existing objective inspection view with escaped settlement reason/summary.
