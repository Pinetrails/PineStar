# PS-2026-012 — Atomic Coordinator Intake & Decomposition

**Date:** 2026-08-27  
**Status:** Complete

## Intent

Implement Coordinator/Chief-of-Staff as a thin system-role orchestration layer over durable objectives, the role router, admission, activation, and settlement. Preserve direct specialist work and all existing approval, authentication, cancellation, E-stop, permission, and runtime controls.

## Implementation

- Added bounded deterministic intake classification for obvious coordination, Scout, audit, development, and research work. Explicit declared capabilities remain authoritative; unknown work is not guessed into a privileged capability.
- Added optional direct `targetRoleId` intake. It assigns only an active role that satisfies every declared capability and the model-tier ceiling; otherwise it escalates fail-closed.
- Added one-transaction durable decomposition for 2–8 children, maximum depth 3 and bounded payload. The transaction validates the coordinator parent and all dependency indexes before committing parent state or any child.
- Persisted stable parent IDs, child IDs, predecessor relationships, classification, routing, role/tier assignment, approval state, and an idempotent decomposition identity. Protected children remain `approval_required`; unroutable children remain escalated.
- Admission now rejects a child until every declared predecessor is durably completed. Real runtime settlement and pre-run cancellation invoke atomic parent reconciliation.
- Parent aggregation reports active, waiting for child approval, blocked after required child failure/cancellation, or completed after all children complete. Completion evidence contains bounded child objective references, not transcripts.
- Added authenticated `POST /api/objectives/intake` and `POST /api/objectives/decompose`. Existing list APIs and the Reports surface expose escaped parent, dependency, and child relationships.

## Safety boundaries

- Decomposition creates records only. It cannot approve, admit, activate, grant tools, publish, message externally, spend, or access credentials.
- The existing runtime activation, provider readiness, permissions, E-stop, cancellation, audit, and settlement machinery remains authoritative.
- No external action or push occurred.
