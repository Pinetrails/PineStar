# PS-2026-017 — Away/Night Shift Objective Bridge

**Date:** 2026-08-27  
**Status:** Complete

## Intent

Make explicitly selected Pine Star objectives available for unattended Away work through the proven StarNet Night Shift lifecycle, without creating another timer, execution engine, permission system, or halt path.

## Implementation

- Added durable per-objective Away metadata with queued, claimed, completed, blocked, and cancelled states.
- Enqueue is idempotent and accepts only safe objectives already in assigned or admitted state. Protected and approval-required objectives are rejected before entering unattended work.
- The existing Night Shift pre-spend gate recognizes ready Away work. Presence, unattended posture, daily leash, cooldown, concurrency, durable halt, and persistence-before-fire remain owned by the existing Night Shift planner/driver.
- A fired beat atomically claims one objective, runs normal Pine Star admission when needed, then uses shared activation and settlement. The ambient Night Shift workflow remains the fallback when no objective is queued.
- E-stop aborts the existing Night Shift beat signal, which propagates to the objective's existing run controller. Normal objective cancellation remains available after activation.
- Failed pre-activation attempts requeue only for bounded transient conditions. Three claims is the hard retry ceiling; stale claims become reclaimable after one hour for restart recovery.
- Added authenticated GET/POST/DELETE `/api/objectives/away` for inspection, explicit enqueue, and queued-work cancellation.

## Safety

- Enqueue grants no approval, role, provider, tool, filesystem, credential, publishing, messaging, purchase, or spending authority.
- Existing objective admission, runtime identity binding, permissions, zero-spend defaults, E-stop, cancellation, audit, and settlement remain authoritative.
- No external action, destructive migration, new scheduler, push, or automatic approval was introduced.
