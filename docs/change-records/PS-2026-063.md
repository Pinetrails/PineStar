# PS-2026-063 — Runtime champion configuration identity

## Purpose

Make the real Pine Star runtime configuration used by an objective durably identifiable before establishing the first Auditor champion.

## Changes

- Added stable `configurationId` to the existing roster load/save contract and made it mandatory for objective admission.
- Bound the configuration ID into objective admission state and passed it through normal objective execution.
- Added configuration ID and observed provider to durable run history alongside the existing model, reasoning, usage, cost, timing, recovery, and completion facts.
- Added a bounded append-only non-secret configuration-snapshot audit to the existing roster envelope.

## Safety

- No credential value is stored or exposed by the configuration identity or audit fields.

- The change uses the existing roster, objective, and run mechanisms and adds no parallel configuration or unrestricted execution API.
- Challenger activation and measurement execution remain separately unauthorized.
