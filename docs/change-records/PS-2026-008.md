# PS-2026-008 — Durable Objective Records and Runtime Role/Objective APIs

**Date:** 2026-08-27  
**Status:** Complete  
**Type:** Phase 4 agent/objective runtime foundation  
**Git commit:** The commit containing this record

## Purpose

Compose the pure role registry/router into the authenticated sidecar and preserve objective routing decisions across restarts without conflating system roles with visible StarNet agent instances.

## Implementation

- Added a bounded, crash-safe station objective store at `pine-star.objectives.json`, outside every agent filesystem jail.
- Persisted declared capabilities, routing result and reason, stable assigned role ID, assigned and maximum model tiers, approval state, timestamps, and completion-evidence references.
- Added authenticated `GET /api/roles`, `GET|POST /api/objectives`, and `POST /api/objectives/status` contracts.
- Required evidence references before an objective can become `completed`.
- Persisted protected objectives as `approval_required` and rejected status changes through the general status route. No execution or approval-grant path was added.
- Kept role records separate from visible agent names, specialties, roster instances, provider choices, and model identifiers.
