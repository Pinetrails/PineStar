# PS-2026-061 — Commander experiment review

## Purpose

Add the protected decision boundary required before a bounded local experiment may later execute, without conflating experiment approval with execution or configuration activation.

## Changes

- Added a SHA-256 digest over every immutable experiment term so Commander review is bound to the exact proposal.
- Added an authenticated approve/reject endpoint requiring the experiment ID, exact digest, action, and rationale.
- Decisions are one-way, idempotent only for an exact retry, and retained with a bounded durable workflow audit event.
- Approval changes only the proposal's review and execution-authorization state. Rejection grants no execution authority.

## Safety

- A decision performs no experiment run, creates no objective, and schedules no retry or rerun.
- Permitted cost and spending authority remain exactly $0; external action and side effects remain forbidden.
- Experiment approval cannot change a configuration or authorize configuration activation. Any later activation remains a separate protected Commander decision.
- Existing audit, E-stop, credential, financial, publication, and external-action controls remain authoritative.
