## Runtime trace

- Authenticated `/api/run` is the watched transport adapter. It validates input, creates the run ID and abort controller, registers the run in `runs`/`runsMeta`, and supplies the live fail-closed consent channel.
- `runOnce` is the shared execution authority used by interactive, cron, Night Shift, Workshop, channel, and delegated work. It owns concurrency and provider/billing admission, capability/permission enforcement, run journals, durable transcripts, run outcome records, failure settlement, and tool-side-effect audit boundaries.
- `/api/cancel` aborts the controller in the shared `runs` map. `/api/halt` aborts every such run and establishes durable stand-down for autonomous schedulers.
- Runtime identity comes from the durable roster. Visible name and free-form roster `role` are presentation/context fields, not system-role authority.

## Implementation

- Added a pure dispatch-admission module bridging durable objectives, routed roles, explicit roster bindings, halt state, and an injected existing-runtime admission check.
- Added `systemRoleIds` to the known durable roster contract. A role must bind to exactly one complete roster identity; missing, invalid, ambiguous, or unavailable identities fail closed.
- Added authenticated `POST /api/objectives/admit`.
- Admission verifies assigned/non-protected objective state, active role, autonomous halt state, runtime identity, configured provider credential, and model readiness.
- Successful admission mints a future run ID, moves the objective to `admitted`, and durably records the role, runtime agent, timestamp, decision, and reason.
- Rejections are also durably audited while leaving an assigned objective consistently retryable.
- Admission explicitly reports `executionStarted:false`. It does not invoke a provider, grant consent, widen tools, spend, publish, message externally, or bypass E-stop.
