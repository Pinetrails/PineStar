# PS-2026-045 — Verified Local Product Artifact Admission

**Date:** 2026-09-04
**Status:** Complete

## Intent

Provide a narrow, authenticated provenance path for verified owner-supplied local product files so they can enter the existing deliverable and QA systems without broad filesystem ingestion or any external authority.

## Results

- Added `POST /api/product-projects/local-artifacts`, protected by the existing sidecar token and limited to files beneath roots explicitly configured through `STARNET_PRODUCT_IMPORT_ROOTS`.
- Requires an existing product project, stable artifact identity, and declared SHA-256; verifies the source bytes before writing and verifies the canonical copy afterward.
- Resolves real paths as well as lexical paths so a symlink cannot escape an allowed root.
- Copies matching bytes into `WORKSPACES/product-artifacts/<project>/<artifact>/`, leaving the source untouched.
- Records the canonical path, byte count, source path, and verified hash in the existing deliverable ledger with status `verified`; matching retries are idempotent and identity/destination conflicts are refused.
- The existing product QA gate now recognizes `verified` alongside kept/implemented Workshop evidence. No QA result is granted by admission alone.

## Safety boundaries

- No import roots are enabled by default; the route cannot ingest until an operator explicitly configures at least one local root.
- No directory ingestion, discovery, upload, publication, account, credential, purchase, payment, network action, or source-file mutation was added.
- `externalAction` remains false and spending authority remains `$0`.
