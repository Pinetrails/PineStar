# PS-2026-038 — Protected Publication Request Withdrawal

**Date:** 2026-09-03
**Status:** Complete

## Intent

Allow a user to retract a still-waiting publication approval request without approving, executing, erasing, or silently abandoning it.

## Implementation

- Added authenticated `POST /api/product-projects/publication-approval-withdrawal` with stable project/request identity and a required bounded reason.
- Added an objective-store withdrawal operation limited to protected objectives in `approval_required` with `approvalState: required`.
- Withdrawal records `status: cancelled`, `approvalState: withdrawn`, the reason, completion timestamp, and a bounded `approval_withdrawn` workflow-audit event.
- Creates and links a shared withdrawal report, then returns the matching project from `approval_required` to `listing_ready` through a private workflow option.
- Generic project updates cannot bypass either approval request or withdrawal.
- A repeated identical withdrawal reuses the cancelled objective and report without adding audit events.

## Safety

- Nonprotected objectives and protected objectives outside the waiting state are refused.
- Withdrawal cannot approve, admit, assign, run, or publish the objective.
- The response preserves `externalAction:false`, `publicationPerformed:false`, and `spendingAuthorityUsd:0`.
- Authentication, QA/artifact evidence, audit, E-stop, cancellation, and protected routing remain intact.
- No marketplace write, account, credential, purchase, subscription, or spend was added.
