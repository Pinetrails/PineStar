# PS-2026-039 — Terminal Publication Request Identity

**Date:** 2026-09-03
**Status:** Complete

## Intent

Keep project, objective, and publication state truthful after withdrawal by preventing a cancelled stable request identity from being reused as if it were still pending.

## Implementation

- Refuse a publication approval request when its stable request ID belongs to a withdrawn objective.
- Refuse any other existing request identity that is not a protected objective still waiting in `approval_required`.
- Permit revised review through a new stable request ID, which creates a separate protected stopped objective and retains the withdrawn history.
- Restore `publicationState: not_published` when the protected withdrawal seam returns a project to `listing_ready`.

## Safety

- Refusal happens before report linking or project mutation.
- A new request remains protected, unassigned, authenticated, and incapable of execution.
- No approval grant, publication executor, marketplace write, account, credential, purchase, subscription, or spending authority was added.
- Existing E-stop, cancellation, audit, QA-evidence, and authentication boundaries remain unchanged.
