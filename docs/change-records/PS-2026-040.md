# PS-2026-040 — Single Pending Publication Review

**Date:** 2026-09-03
**Status:** Complete

## Intent

Prevent competing protected publication reviews from making product state ambiguous, and handle any legacy concurrent records truthfully during withdrawal.

## Implementation

- Refuse a new request ID when the same product already has a protected objective waiting in `approval_required`.
- Preserve normal idempotency for the matching active stable request ID.
- After withdrawal, inspect existing objective truth for another pending review on the same product.
- Keep the project in `approval_required` and return `remainingPendingObjectiveId` while another review waits; restore listing readiness only after the last pending review is withdrawn.

## Safety

- The new check only refuses ambiguous request creation; it grants no authority.
- Legacy handling never cancels a different request and never clears a truthful approval boundary.
- Protected objectives remain unassigned and unable to run through normal execution paths.
- No approval grant, publication executor, marketplace write, account, credential, purchase, subscription, or spending authority was added.
