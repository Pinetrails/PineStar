# qa/eval-receipts — durable, committed eval-gate receipts

This directory is the **committed** home for credential-free eval-gate receipts.
It exists because `.dogfood/` is gitignored wholesale (`.gitignore`), so the signed
receipts from past live campaigns (e.g. the Aug 3–6 v0.9.0 campaign) were never
recoverable from git — only their committed hash indexes under `docs/baselines/`
survive. Receipts written here are ordinary tracked files: committing them is what
makes them durable, and their history is the audit trail.

## What is here

- `last-gate-receipt.json` — the most recent run of `npm run eval:gate`
  (schema `starnet.eval.gate-receipt.v1`). One compact JSON receipt covering the whole
  credential-free slice: pack file sha256s, expected/parsed row counts, per-step exit
  codes and wall times, per-pack verdicts, grader identity, git commit, and an explicit
  honesty block. The stable filename is intentional — each meaningful run overwrites it,
  and git history preserves every committed version.

The same receipt is regenerated by CI (`.github/workflows/eval-gates.yml`) on every PR
and trunk push, printed to the job log, and uploaded as a build artifact.

## What these receipts PROVE

- The frozen v0.9.0 comparison contract still validates against the live claims ledger.
- The 13-row deterministic agent-quality pack reproduces its committed baseline through
  the real `runAgentLoop`.
- The 10 run-boundary fault scenarios pass all 100 repeats each (1000 host-observed
  rows) under the frozen contract's fault gauntlet.
- The 32 parity scenarios' fixture-host oracles, host observation/routing capture, and
  the independent grader all work end-to-end with a scripted in-process provider — and
  the grader **detects** each zero-tolerance violation class (falseDone,
  wrongDestination, duplicateMutation, authorityEscape) when a probe deliberately
  commits it.

In one sentence: **they prove harness plumbing at a given commit.**

## What these receipts do NOT prove

- **Not model quality.** No live model produced any output (`honesty.liveModel:false`
  is asserted in code). A scripted provider passing a scenario says the rails work, not
  that any real model would pass it. This is the same honesty class as the campaign
  preflight test: a green preflight proves the spend gate refuses correctly, not that
  the campaign passes.
- **Not an installed candidate.** These are source-tree runs
  (`honesty.candidateBound:false`); no executable binding, no provenance verification.
- **Not the frozen v0.9.0 contract gates.** The offline parity rows can never satisfy
  them (`honesty.satisfiesV090ContractGates:false`, enforced by
  `assertPlumbingReceipt`/`assertGateReceiptHonesty` in code): the contract requires an
  installed bound candidate, live provider keys, 3 attempts per scenario per harness,
  and the frozen Hermes reference.
- **Not signed** unless `honesty.signed:true` — the default gate receipt is unsigned.

## Where full live campaigns live

Full provider-backed campaigns (bound manifests, Ed25519-signed fault/parity/
performance/soak receipts, raw trajectories) still run under `.dogfood/` and stay out
of git; only their hash indexes are committed under `docs/baselines/`. See
`scripts/eval/README.md` for the campaign procedure and for the open decisions on the
superseded Hermes pin and the Aug 3–6 falseDone reds.
